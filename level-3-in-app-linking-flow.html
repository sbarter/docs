Level 3 Flow

In-App Linking

This page shows the public Level 3 in-app linking flow. Sbarter asks the Game Studio to confirm a known provider account inside the game, and the Game Studio sends the final result back to Sbarter.

Scope: This is a linked-first flow. Sbarter already knows the providerUserId that must be confirmed.
Step 1: Sbarter asks

POST /v1/sbarter/gamer/validate/in-app

Step 2: VGP sends result back

POST /v1/linking/in-app/{requestId}

Implementation Rules

Public integration rules for the Game Studio:

  • Use providerUserId to find the exact player inside the game.
  • Show the link-confirmation prompt before expiresAt.
  • Get an OAuth bearer token before calling Sbarter back.
  • Do not build the callback URL yourself. Use the exact webhookUrl sent by Sbarter.
  • Always send back the final decision: accepted, rejected, or expired.
  • Always send confirmedAt when reporting the final result.
  • If the player accepts, also send providerDisplayName, profileCapturedAt, and profileStats.
