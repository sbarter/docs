Level 3

How Level 3 Works

A level 3 game is integrated with Sbarter by its studio: players link their game account to Sbarter once, Sbarter tells the studio about each challenge match, and the studio's server reports who won. Sbarter settles the challenge and pays out automatically.

Two directions: the Sbarter API is what your backend calls on Sbarter (OAuth2 client credentials); the VGP API is what your backend implements and Sbarter calls (X-API-Key). Both are in the API reference - switch between them in the selector.
Sbarter API host

partners.<env>.sbarter.com/<slug>

VGP API host

your base URL, given to Sbarter per environment

Architecture

  • One host per studio. Your backend calls partners.<env>.sbarter.com/<slug>; the slug is given by Sbarter at onboarding.
  • An adapter on Sbarter's side. It checks your token (it carries your studio id), calls your API with the key you issued, and builds the callback URLs Sbarter sends you.
  • Your own API. If your studio already has an API for this, Sbarter can map to it in your adapter instead of you implementing the VGP API.

Onboarding

  • Sbarter API credentials. Sbarter web portal → your studio → API credentials: create a client, keep the secret (shown once). Scopes: linking.write, linking.deeplink.write, linking.read, webhook.write.
  • VGP API credentials. Send Sbarter your base URL and an API key per environment.
  • providerGameId. Sbarter registers each of your games with the id you use for it in every call.
  • Smoke test. Get a token and call GET /v1/auth/check: 204 means token, studio and gateway all work.

Linking a game account

  • From the Sbarter app: In-App Linking Flow - the player enters their game id in Sbarter, you confirm it inside your game.
  • From your game: Deep Link Flow - your game mints a one-time link, the player opens it in Sbarter.
  • One game account can be linked to one Sbarter player only (GI0023).

A challenge match

  • Register. When both players are ready Sbarter calls POST /v1/session with sessionId, both players (your providerUserId + Sbarter internalId), the rules, expiresAt and a webhookUrl.
  • Report. When the match ends, call the webhookUrl with sessionId, your matchId, status (win, draw, failed, voided) and exactly two players with their outcome.
  • Retries are safe. sessionId + matchId is the idempotency key: a repeated result is recognised, never applied twice.
